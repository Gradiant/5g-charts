# Gradiant 5G Charts

This repo mantains helm charts generated by [Gradiant](https://www.gradiant.org) for its Lab5G platform.

Gradiant is actively researching and developing Cloud-Native Network Functions (CNFs) with special focus on 5G network and evolvable to 6G technologies.

Follow the README.md of each chart to evaluate the technologies in your kubernetes cluster.

## Install chart from DockerHub repository

charts in `charts/`` folder are packaged and available at Gradiant's DockerHub repo:  

[https://hub.docker.com/u/gradiant](https://hub.docker.com/u/gradiant)

You can pull and save locally the chart. For example:

```bash
helm pull oci://registry-1.docker.io/gradiant/open5gs --version 2.2.0
```

You can directly install the chart. For example, to install open5gs:

```bash
helm install open5gs oci://registry-1.docker.io/gradiant/open5gs --version 2.2.0
```

## Check out our tutorials

We have developed some tutorials meant to **guide you through the combined deployment of different technologies**. It is an easy and quick way of testing these technologies and exploring how they work.

These tutorials make use of charts available at this repo, and their corresponding documentation can be found at:
[https://gradiant.github.io/5g-charts/](https://gradiant.github.io/5g-charts/)

### Executable UERANSIM tutorial

The maintained source for the Open5GS + UERANSIM tutorial is
[`tutorials/open5gs-ueransim`](tutorials/open5gs-ueransim). Its `tutorial.sh`
contains the commands used by readers and by `.github/workflows/tutorial-ueransim.yml`.
`versions.json` pins the published chart versions; `tutorial.md.in` is the Pages
source. The existing public tutorial URL is preserved.

- Chart pull requests test candidate charts on a fresh Kind cluster. Changes to
  the tutorial also test the pinned public packages. Neither can publish documentation.
- A successful **Release Charts** run tests the newly published versions. When
  the pins change, a separate trusted job opens a documentation PR with the
  recorded proof. It never overwrites an existing review branch.
- Merging tutorial changes to `main` repeats the published-package test and only
  then updates this tutorial's files in `gh-pages` and requests a Pages build.
  The pipeline waits for that build and checks the public page's source commit.
- Weekly and manual runs recheck the documented versions without publishing.

All functional checks, including per-UE registration, PDU sessions, traffic and
cleanup, must pass. Artifacts record package hashes, runtime image digests,
tool/kernel versions and the source fingerprint. Candidate or stale evidence
cannot render a public page. This test does not validate other tutorials or
interactive WebUI forms.

Published-package checks also build a preview with the existing Jekyll site.
The preview is attached as an artifact; it does not change live Pages.

The repository Actions policy must allow GitHub Actions to create pull requests.
Only the trusted proposal job receives PR/contents/actions write permissions;
only the publication job receives Pages write permissions. Neither runs PR code.
Bot PRs explicitly dispatch the read-only checks; no personal token is required.

## Development

- clone repo
- adjust given chart
- bump chart version if required
- run tests
- create pull request with issue id, attach test results if possible

### Requirements

- linting requires docker
- running test-install.sh requires docker and kubernetes-in-docker.
- `tee` console tool to output to the console and file in the same time

### Chart documentation

Generate the Open5GS and MongoDB READMEs locally with Docker:

```bash
bash scripts/doc-gen.sh
```

To regenerate selected charts:

```bash
bash scripts/doc-gen.sh charts/open5gs-upf charts/mongodb
```

The script pins `helm-docs` to `v1.14.2`. Metadata and default values come from
`Chart.yaml` and `values.yaml`. Add descriptions immediately above values using
`# -- Description`. Edit explanatory sections in each chart's `README.md.gotmpl`;
shared metadata formatting lives in `charts/_helm-docs.gotmpl`. Regenerate the
READMEs after changing these sources, and review the resulting diff.

## Linting and testing full deployment

We use helm [chart-testing](https://github.com/helm/chart-testing) running a docker image.

An example to test specific chart lint and install, send console logs also to the log file `reports/*.log`:

```bash
scripts/lint-install.sh open5gs | tee reports/open5gs.log
```
